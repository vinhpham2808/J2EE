# SECTION 5: WORKSHOP — SECURING HYBRID TRAFFIC TO AMAZON S3 USING VPC ENDPOINTS

> **Integrated Project:** Money Manager (Personal Finance Management)
> **Practical Use Case:** Storing receipt images for AI OCR parsing and financial reports exporting.
> **Lab Step-by-Step Guide - Non-Coding & Configuration-Free Version**

---

## 5.1. WORKSHOP OVERVIEW

### 5.1.1. Context within Money Manager Project
In the **Money Manager** system, users upload receipt images from mobile devices or web clients. These images are stored in an Amazon S3 Bucket to be analyzed by the AI OCR service (Gemini Vision) to extract transaction fields automatically. Additionally, financial reports in Excel format generated by the Spring Boot backend are stored on S3 for secure download via presigned URLs.

According to AWS best practices, Spring Boot backend servers are deployed inside **Private App Subnets** (without public IPs and no direct internet routing) to enforce security boundary.

However, S3 is a public service residing outside the VPC. Connecting from a private EC2 instance to S3 typically goes through a NAT Gateway, which introduces:
1. **Cost:** High data transfer pricing through NAT Gateways when processing massive receipt image uploads.
2. **Security:** Traffic goes through the public internet, raising security compliance concerns.

### 5.1.2. Solution: AWS PrivateLink & VPC Endpoints
To establish secure, private connections to S3, this workshop guides you to implement two types of VPC Endpoints:
1. **In-Cloud Access (VPC-to-S3):** Configure a **Gateway VPC Endpoint**. It is free of charge and automatically routes internal S3 calls by modifying the VPC's route tables.
2. **Hybrid Access (On-Premises-to-S3):** Configure an **Interface VPC Endpoint** combined with a **Route 53 Inbound Resolver**. Since Gateway Endpoints cannot be reached from outside the VPC (e.g., from local developers testing mobile code via VPN/Direct Connect), the Interface Endpoint provides Private IPs inside the VPC to solve this hybrid challenge.

## 5.2. PREREQUISITES

### 5.2.1. Required AWS Resources
1. **VPC:** One VPC with `10.0.0.0/16` IP CIDR block.
2. **Subnets:**
   * `Public-Subnet-A` (`10.0.1.0/24`) attached to an Internet Gateway (IGW).
   * `Private-Subnet-A` (`10.0.2.0/24`) for running the Backend.
3. **EC2 Instances:**
   * `EC2-Backend-App`: Located in `Private-Subnet-A`, running the Spring Boot backend. No public IP.
   * `EC2-OnPremises-Simulator`: Running in a simulated network (or a separate public subnet) representing a remote developer machine connecting via VPN.
4. **S3 Bucket:** Name it `moneymanager-receipts-secure-prod` (Use a globally unique name).
5. **IAM Role:** An IAM Instance Profile role attached to `EC2-Backend-App` granting access to S3.

---

## 5.3. IN-CLOUD VPC-TO-S3 ACCESS (Using Gateway VPC Endpoint)

### 5.3.1. Create Gateway VPC Endpoint for S3
1. Open the AWS Console and navigate to the **VPC** dashboard.
2. From the left menu, select **Endpoints** → Click **Create endpoint**.
3. **Name tag:** `vpce-s3-gateway-moneymanager`.
4. **Service category:** Select **AWS services**.
5. **Service name:** Search for `s3`. Select the service name ending in `.s3` with Type **Gateway** (e.g., `com.amazonaws.ap-southeast-1.s3`).
6. **VPC:** Select your prepared VPC.
7. **Route tables:** Select the Route Table associated with `Private-Subnet-A`. This automatically injects S3 route target rules.
8. **Policy:** Select **Full access** (we will configure granular authorization in later sections).
9. Click **Create endpoint**.

### 5.3.2. Verify the Gateway VPC Endpoint
1. Use **AWS Systems Manager Session Manager** to SSH into the private `EC2-Backend-App` server.
2. Inspect the current operating system route table. Note the prefix list target addition representing S3 IP ranges mapped to the Gateway Endpoint ID.
3. Try uploading a sample receipt image using AWS CLI:
   ```bash
   # Generate fake invoice file
   echo "fake-receipt-data" > receipt_001.jpg

   # Upload to S3
   aws s3 cp receipt_001.jpg s3://moneymanager-receipts-secure-prod/userData/intern_test/
   ```
4. Verify routing path: Resolve the S3 bucket DNS endpoint:
   ```bash
   nslookup moneymanager-receipts-secure-prod.s3.ap-southeast-1.amazonaws.com
   ```
   *While it resolves to public S3 IPs, the physical network path bypasses the IGW/NAT Gateway and routes internally within the AWS global network backbone.*

## 5.4. HYBRID ON-PREMISES-TO-S3 ACCESS (Using Interface VPC Endpoint)

Gateway Endpoints cannot receive traffic routed through VPNs or AWS Direct Connect. Consequently, mobile developers working at remote branches cannot test S3 integrations privately without opening S3 public access. To enable hybrid secure connections, we deploy an **Interface VPC Endpoint**.

### 5.4.1. Network Setup
1. Establish a mock VPN tunnel or VPC peering from the `EC2-OnPremises-Simulator` to the main AWS VPC.
2. Create a Security Group for the interface endpoint:
   * Name: `sg-s3-interface-endpoint`.
   * **Inbound Rules:** Allow port `443` (HTTPS) from the On-Premises IP ranges (e.g. `10.1.0.0/16` or local office subnet `192.168.1.0/24`).

### 5.4.2. Create S3 Interface VPC Endpoint
1. Navigate to **VPC** → **Endpoints** → Click **Create endpoint**.
2. **Name tag:** `vpce-s3-interface-moneymanager`.
3. **Service category:** Select **AWS services**.
4. **Service name:** Search for `s3`. Select the service name ending in `.s3` with Type **Interface**.
5. **VPC:** Choose your VPC.
6. **Subnets:** Select Private Subnets in multiple AZs for high availability.
7. **Security groups:** Select the `sg-s3-interface-endpoint` group created in step 5.4.1.
8. **Policy:** Select **Full access**.
9. Click **Create endpoint**.

### 5.4.3. Test S3 Interface Endpoint from Simulated On-Premises Machine
AWS generates custom Endpoint DNS names (e.g., `vpce-xxxx-ap-southeast-1.vpcs3.amazonaws.com`).
1. Connect to `EC2-OnPremises-Simulator`.
2. Find the Interface Endpoint DNS names under the **Details** tab on the AWS Console.
3. Test uploading file to S3 by specifying the `--endpoint-url`:
   ```bash
   # Upload receipt using S3 Interface Endpoint DNS
   aws s3 --endpoint-url https://bucket.vpce-s3-interface-moneymanager.s3.ap-southeast-1.vpce.amazonaws.com cp onprem_receipt.jpg s3://moneymanager-receipts-secure-prod/userData/onprem_test/
   ```
4. Verify the file exists in the S3 bucket via AWS Console.

### 5.4.4. Set Up On-Premises DNS Simulation (Route 53 Inbound Resolver)
To avoid hardcoding endpoint URLs in mobile apps or client code, deploy a Route 53 Resolver to forward default S3 DNS requests automatically.

1. Go to **Route 53** → **Resolver** → **Inbound endpoints** → Click **Create inbound endpoint**.
2. **VPC:** Select the VPC of the main deployment.
3. **IP addresses:** Choose 2 subnets across different AZs. AWS allocates private resolver IPs.
4. At the On-Premises machine, configure the local DNS forwarder to redirect `*.s3.ap-southeast-1.amazonaws.com` lookup requests to these resolver IPs.
5. Verify using normal AWS CLI commands without custom endpoint parameters:
   ```bash
   # S3 calls now resolve privately and run over VPN automatically
   aws s3 cp test_dns_receipt.jpg s3://moneymanager-receipts-secure-prod/userData/dns_test/
   ```

## 5.5. VPC ENDPOINT POLICIES (ADVANCED SECURITY)

To enforce the Principle of Least Privilege and prevent data exfiltration to private AWS accounts, configure VPC Endpoint Policies.

### 5.5.1. Configure VPC Endpoint Policy
1. Select Endpoint `vpce-s3-gateway-moneymanager`.
2. Click **Policy** tab → **Edit policy**.
3. Restrict S3 API access exclusively to the target bucket. Define policy statements allowing only basic actions (`GetObject`, `PutObject`, `ListBucket`) for the target project resources (`arn:aws:s3:::moneymanager-receipts-secure-prod` and its children), while denying access to any other external buckets.

### 5.5.2. Restrict S3 Bucket Policies to Endpoints Only
Add S3 Bucket policy deny statements blocking all S3 actions if requests do not originate from either the Gateway or Interface endpoints. This prevents public internet exposure or unauthorized VPC traffic from querying the bucket.

## 5.6. CLEAN UP RESOURCES

Tear down resources once verified to avoid AWS bills:

1. **Delete S3 objects and Bucket:**
   ```bash
   aws s3 rm s3://moneymanager-receipts-secure-prod --recursive
   aws s3api delete-bucket --bucket moneymanager-receipts-secure-prod --region ap-southeast-1
   ```
2. **Delete VPC Endpoints:**
   * Select `vpce-s3-gateway-moneymanager` → Click **Actions** → **Delete VPC endpoints**.
   * Select `vpce-s3-interface-moneymanager` → Click **Actions** → **Delete VPC endpoints**.
3. **Delete Route 53 Resolver Inbound Endpoint:**
   * Select the Inbound Resolver → Click **Delete**.
4. **Terminate EC2 instances:**
   * Terminate `EC2-Backend-App` and `EC2-OnPremises-Simulator`.
